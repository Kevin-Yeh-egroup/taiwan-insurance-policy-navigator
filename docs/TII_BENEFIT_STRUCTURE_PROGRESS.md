# TII 保障結構化進度

更新日期：2026-07-20

## 完成定義

一筆商品版本只有在下列條件全部成立時，才算有 Verified Benefits：

1. 以 `batch_id + product_id` 保存版本，不以商品名稱去重。
2. 金額、計畫或單位來自同一份條款文件。
3. 每個給付都有條款或附表來源位置。
4. 來源 PDF 雜湊、條款文字雜湊、解析結果雜湊及審核資料均已保存。
5. 公開資料只保留結構化結果與短來源說明，不包含完整條款文字。

## 後續順序

1. 健康保險：下一組為富邦人壽新防癌終身健康保險第 4 至第 6 次變更共 3 個商品版本，再處理其餘固定計畫型。
2. 傷害保險：固定計畫型；需要保險金額的複合型另走公式模型。
3. 傳統型壽險：先處理保險金額固定倍數型，再處理終身壽險複合公式。
4. 傳統型及投資型年金：以年金開始前／開始日／開始後分階段保存公式與必要輸入。
5. 投資型壽險：保存甲型／乙型、保額、帳戶價值及事故評價時點公式，不冒充固定金額。
6. 產險四類：完成條款下載後，再使用同一個提案、審核及公開安全流程。

## 續跑與停止條件

- 每輪最多新增 4 個條款版型，完成解析、提案、來源審核、公開摘要與測試後才進下一個版型。
- 已有 `coverage_entries` 或 `plan_options.coverage_entries` 的 `batch_id + product_id` 自動略過。
- 同一商品若多份條款解析出不同金額，標成 `manual_review_required`，不得自動發布。
- 動態公式缺少保額、帳戶價值、年金因子或事故時點時，只能顯示條款公式與必要輸入，不顯示推估保障金額。
